# Проверки

Команды из корня проекта (PowerShell):
- Для сборки и запуска нужна JDK 25; проверь `JAVA_HOME` и Gradle JVM в IDE.
- `.\gradlew.bat build` — сборка и проверки, включая Detekt.
- `.\gradlew.bat detekt` — отдельный запуск линтера.
- `.\gradlew.bat test` — тесты; сейчас тестовых исходников нет
  и задача завершается как NO-SOURCE.
- `.\gradlew.bat runClient` — запуск клиента для ручной проверки GUI.
  После изменений GUI проверь открытие по R, переключение страниц,
  отображение блоков и весов, применение настроек и повторное открытие.

# Особенности кода

- Minecraft client API, GUI и виджеты находятся в `src/client`.
  В `src/main` остаются предмет, серверная логика, модели и пакеты;
  не добавляй туда зависимости от клиентских классов.
- GUI — клиентский редактор настроек на LibGui:
  `RandomBlockPlacerItemScreen` наследуется от `CottonClientScreen`,
  `RandomBlockPlacerItemGuiDescription` — от `LightweightGuiDescription`.
  `RandomBlockClient.registryKeybinds()` открывает экран напрямую по R.
  `ScreenHandlers.kt`, серверное меню и `ClientProxy` удалены.
- В GUI обращайся к текущей странице через `ValueRef` /
  `MutableValueRef` (расширения `.ref` / `.mutableRef`): страница меняется
  без пересоздания GUI. Для полей вложенной модели получай текущую страницу
  внутри getter/setter, не захватывай объект прежней страницы.
  При переключении страниц вызываются `update()` у панелей блоков и весов.
- `WBlocksPanel` показывает сетку 3×3 через `WItem` в `WPlainPanel`.
  `WItemSlot.SLOT_TEXTURE` используется только как фон ячейки.
  Это не инвентарные слоты: `InventoryFromList` удалён, реальных предметов
  в редакторе нет. Не добавляй перенос, расходование или выдачу предметов
  при выборе блоков. Каталог блоков с прокруткой пока не реализован.
- Кнопка «Применить» вызывает `onApply(PlayerPages)`; callback из
  `RegistryKeybinds.kt` обновляет `RandomBlockClient.playerPages` и отправляет
  `PlayerBlocksListsPayload`. GUI редактирует исходный изменяемый объект,
  поэтому закрытие без применения не отменяет локальные изменения
  и само по себе не отправляет их серверу.
- `RandomBlockClient` читает `config/randomblock_config.json` при создании
  экземпляра (в dev-запуске — `run/config/randomblock_config.json`).
  На JOIN метод `loadConfig()` отправляет уже загруженные настройки серверу;
  на DISCONNECT `saveConfig()` записывает их в файл.
- Сервер хранит настройки по UUID в `RandomBlockPlacerItem` и выполняет
  установку блоков. Клиентский редактор не заменяет серверную проверку
  входящих настроек и правил работы с миром и инвентарём.
- `OpenGuiPayload` пока остаётся в исходниках и регистрации пакетов,
  но для открытия экрана не используется; серверный обработчик удалён.
- При изменении сериализации учитывай оба потребителя:
  локальный конфиг и `PlayerBlocksListsPayload` используют
  одни и те же модели `PlayerPages`.
- При переименовании класса предмета учитывай, что его registry ID
  вычисляется из имени класса в `RegisterItems.kt`; проверь связанные
  ресурсы и ключи локализации.
